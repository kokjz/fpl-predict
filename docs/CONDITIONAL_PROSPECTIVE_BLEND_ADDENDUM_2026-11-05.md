## What it adds
- **One secondary candidate for phase 2:** `blend_equal`, the equal-weight average of the two frozen phase 1 models' core-points forecasts.
- **No new fit and no new data:** the weight is fixed at 0.5 in advance, with zero fitted parameters.
- **Nothing else changes:** the frozen protocol, models, window (GW10–GW38) and gates stay as they are.

## Why
The conditional candidate improved error in the inspected 2025/26 sanity check, but scored 2.75 points less on fixed squads. Averaging it with the control is a simple, pre-specified hedge against that selection risk. No blend metric has been computed on any data.

## How phase 2 judges it
- **Same rules:** the same window, the same registry gates 2–7 against the control, and the same fixed squads, seed and selector.
- **The conditional candidate is judged first.**
  - If it passes every gate, it is the only promotion-eligible candidate.
  - Only if it fails and the blend passes every gate does the blend become eligible for a separately authorised promotion brief.
- **No post-hoc choice:** candidates are not chosen between by comparing their phase 2 results, and no other weights or blends are allowed.
- **Reporting:** the phase 2 report must state that two candidates were tested.
- **Timing:** this record is valid for the full window only if it was first pushed before the GW10 deadline (2026-11-06 18:30 UTC). Otherwise the blend's window starts later, and the primary candidate is unaffected.
- **Planner:** any promotion, for either candidate, needs a weekly-planner change so availability is not counted twice.
