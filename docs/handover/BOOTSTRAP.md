# Small receiving-chat bootstrap

The intended receiving workflow is Claude Desktop's **Code** tab, Sonnet5.5 on
Pro, using a local WSL2 environment. This is the user's intended setup, not a
verified receiving account/configuration. Codex or another tool-capable coding
chat can follow the same repository/evidence procedure.

1. Inspect repository/source, open PRs and CHECKPOINT.json. Read PROJECT_CONTEXT.md
   and OPERATING_RULES.md once: they are the compact factual and standing-rule
   map. Read CLAUDE_PRO_WORKFLOW.md and WINDOWS_SETUP.md for setup, then use those
   as reference rather than repeating their contents in every response.
2. Ask only for the private archive location and trusted SHA256 if absent.
   Verify and restore original bytes with tools/portable_handover.py. A clone
   alone has no approved weights or full original research data. Do not attach
   the archive or dump its payload into chat.
3. Read private migration/PRIVATE_RESUME.md and the current-state summary/relevant
   latest prompt entries from CONTEXT_MASTER.md. Use its heading index for
   historical questions; do not read its full prompt log by default. Preserve
   the whole file on disk. Read additional instructions/evidence before actions
   they govern. A summary never overrides actual user instructions or protocols.
4. Recreate/verify the selected environment and approved-artifact smoke oracle.
   Preserve original paths/hashes; use explicit derived relocation maps.
   Windows execution is not already certified by the origin-machine tests.
5. Resume the precise next step: research review findings R1/R2/R3, valid-state
   audit and bounded affected tests, then final PR42 result/document/qualification
   release. The full frozen numerical matrix is already complete; do not rerun
   it or fit another candidate merely to warm up the environment.

Before changing code, state a short step/file/test plan grounded in that evidence.
Continue already authorised work without asking the user to approve routine
choices. Keep meaningful commits/PR scope, exact-source checks and promotion
gates. No weekly squad planning is requested.

Keep a small private RESUME_CURRENT.md with source/branch/PR, approved artifact,
goal/next step, gates/results, unresolved findings, exact commands/test status,
process handles and evidence paths/hashes. Before compaction or a new session,
update it and the private context log. After resuming, revalidate source/PR and
actual process state; do not trust a stale summary as execution proof.

This bootstrap is intentionally small. The comprehensive NEXT_CHAT_PROMPT.md and
the full archive preserve exhaustive context, not an instruction to load all of
it in one turn. Required stage-specific evidence must still be read and checked.
