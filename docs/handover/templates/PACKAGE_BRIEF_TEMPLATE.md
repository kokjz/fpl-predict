## Question, scope and non-goals

State what changes, why and what is already authorised. Separate engineering
repairs from a new scientific hypothesis. List known evidence and uncertainties.

## Data and comparison contract

Record immutable inputs/source hashes, observation/publication/deadline/training
cutoffs, origin-safe rules, chronological split, earlier outcome exposure,
primary/secondary comparators, cohorts, scoring/action space and external
adaptations. Specify planned fit/search/run counts and all failure-retention rules.

## Acceptance and failure criteria

Write error/decision/integrity/consistency/downside/compatibility gates before new
outcomes. Preserve existing gates; describe negative/no-change completion. Keep
code release, research qualification and production promotion separate.

## Execution and evidence plan

List files/components, meaningful tests/audits, exact bounded run matrix,
time/memory/thread/storage limits, new output directories, reuse/hash/prefix
requirements, expected reports and unknown bounds. No unrun result claims.

## Coordination and release

One writer; owned files; brief revision acknowledgement; routine engineering
autonomy; material-deviation boundary; results-packet/review checkpoint; Git/PR/
CI/merge/cleanup/private operational handoff. Record unresolved decisions and
which work can proceed without them. No automatic messaging/model switches.
