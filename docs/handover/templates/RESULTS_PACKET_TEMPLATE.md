# Private results packet — template

Copy outside the public repository before including private paths or evidence.

- Package ID / accepted brief revision/hash / report UTC:
- Programmer / actual model-effort-access (verified vs reported):
- Source before/after, branch, PR and exact tested commit:
- Approved artifact/version/hash before/after; explicit promotion status:
- Input/source/clock hashes and immutable results manifest:
- Current owner / live process handles / terminal status / exact next action:

## Changes and deviations

Describe implementation and why. Separate routine fixes, path/runtime adaptations
and scientific deviations. Record resolution before dependent new work. Never
rewrite old evidence/hash labels or silently revise acceptance criteria.

## Executed validation and comparisons

Give exact commands, actual test outcomes/skips, fit/run counts and measured
resources. Include all primary/secondary case effects, losses, failures, retries,
prefix checks, chronological/legality/arithmetic audits, coverage and unknown
bounds. Keep component versus season results and originals versus adaptations
distinct. Link full evidence by path/hash. Label unrun work explicitly.

## Interpretation requested / response

State the predeclared question and evidence-based uncertainty. Record the
architect's actual response/source/review date if available; otherwise say
pending. Two LLMs' agreement is not an independent dataset or automatic approval.

## Release, usage and remaining work

Record privacy/diff review, exact CI/check state, merge/main sync/branch cleanup,
private weekly operational handoff and source/artifact compatibility changes.
Separate code release, research qualification and production approval. Preserve
all outstanding work. Report observed elapsed effort/rework/defects/handoff cost
and available product usage telemetry; missing/confounded token data is unknown.
No billed API or model switch is implied by this template.
